# Meme MCP 写入协议

所有 Meme Skill 共用这一份操作规则。先发现当前连接的实际工具及 schema，名称可能带服务前缀；不虚构工具或转用另一个账户、服务或 REST 通道。工具能力是上限，用户当前任务决定本次允许的动作。

## 创建记录

仅在用户明确要求保存，或明确的当前范围约定满足触发条件时执行。安装、写权限、表达偏好、旧记录和上游 Skill 的建议都不构成授权。对象清楚时无需二次确认；对象或目标有实质歧义才询问。

用实际 `memo_create` 传 `text` 与新的稳定 `request_key`（UUID）。省略 `project_ids` 使用连接默认项目；受限连接没有默认项目时，只能使用已知获授权的项目 ID 或让用户选择，不猜测、不用空数组绕过范围。正文项目名不等于项目 ID。

默认普通记录，省略 `created_at`；事件日期放在正文，用户明确要求补录日期时才按 schema 使用带时区值。只有真实链接记录才传 `kind: "link"` 和 `url`。用户明确指定的原文、标签和格式优先，不能把 Agent 建议写成用户决定。

## 修改与标签

`memo_update` 会替换完整正文。先按 [读取协议](../SKILL.md) 读完当前记录，保留无关内容，再传 `id`、`expected_version`、`text` 和 `request_key`。保留项目、附件、类型、链接及原日期；正文标签随文字变化。

版本冲突不是重试同一旧正文的理由。重新读取和合并，仍在原授权范围内的修订使用新 key；不能确定如何保留用户新改动时给出冲突，不覆盖。

只有明确要求标签重命名时才用 `tag_rename`：先 `preview`，核对实际影响范围和跳过项，再以 `plan_id` / `request_key` 执行 `apply`。按返回的重试提示或间隔数秒调用 `status` 观察结果；单次交互最多查 5 次，未完成时报告仍在进行及真实 job ID，不重新 apply。已受理不等于全部成功，报告冲突和部分失败。

## 一次意图、一次逻辑写入

写入前在当前任务保留准确的 payload 和 key；不要每次重试重新整理正文。同一意图已有成功回执且内容没有变化时返回原回执，除非用户明确要副本。不为了去重默认扫描整个库。

超时或结果不明时，仅以原 key 和完全相同参数最多重试一次；仍不明则停止，保留草稿与待核实状态。认证、权限、参数错误或幂等冲突不盲重试。上下文丢失导致找不到原 key 时，不用新 key 补发结果不明的写入；先核实或说明无法确认。

收到非错误响应且有真实记录 ID 才确认创建/修改成功；标签任务使用实际状态判断。说明简短，保留回执 ID，不编造链接。错误或没有工具时保留草稿，绝不声称已保存。

Meme MCP 不提供删除、附件上传或项目管理，不借用凭据绕过这些边界。
