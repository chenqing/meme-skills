# Meme · 随手沉淀

负责把选定内容变成一条以后看得懂的记录，并承接回看、项目小结的保存请求。保留用户的原意，不将 Agent 建议改成用户决定。

## 依赖与分工

创建记录前读取 [MCP 写入协议](../meme-mcp/references/write.md)，按其中的创建流程执行；这里不另设重试或去重规则。缺少此文件时保留草稿，说明需要补装 `meme-mcp`，不自行安装或另写一套调用流程。

个性化可用时按 [共享偏好](../meme-shared/SKILL.md) 读取已绑定当前账户的表达设置。没有文件、无法确定账户或用户不需要个性化时，沿用当前表达；不先要求初始化，不默认检索笔记来学习写法。

## 先分清意图

| 当前请求 | 行为 |
| --- | --- |
| “把这个决定记到 Meme”“保存刚才选的那段” | 对象明确就整理并保存，不重复确认 |
| “挑挑这段对话有什么值得记的”“先给草稿” | 提供候选或草稿，零写入 |
| “这次讨论中值得留的内容提醒我” | 本轮低频提醒；确认后才保存 |
| “本次 Cedar 项目中，我拍板的取舍直接保存” | 只在指定范围和条件满足时保存 |

若“记住”可能指 Agent 记忆或另一个笔记服务，先确认目标。安装、MCP 写权限和表达画像都不等于允许自动保存。已有明确指令优先于旧偏好；用户叫停立即停止。仅需本轮提醒时不落盘设置，也不跨会话延续授权。

## 什么时候值得提醒

只有开启提醒后才做这项判断。优先找用户形成了新表达、具有具体背景、以后可能找回的片段：说清楚的疑问或判断、经历后的认识、阅读后的个人理解、决定背后的取舍、失败后可复用的方法。先完成当前任务，再给简短候选；同一话题没有新变化不重复提醒。用户忽略或拒绝就继续。

- 还在比较 A/B：保留探索状态，不写成“决定采用 A”。除非用户要留存推演，否则等结论更清楚。
- 用户拍板并解释理由：可提醒保存决定与原因。
- 只剩一句报错日志：通常跳过；用户说清排障经验时再考虑。
- 用户修正此前判断：保留变化及原因，不能只写新结论而抹去转变。
- 情绪仍在流动、第三方隐私或 Agent 独自发挥：不主动推动保存。

这些是提醒的筛选条件，不是拒绝明确保存请求的理由。用户要存原话、链接、临时备忘或 Agent 建议时照办，并保留归属。

## 草稿要有用户自己的声音

默认一小段，一个中心：必要的背景、用户说了什么、为什么值得保留。不要把每条记录写成完整总结或工作报告。多条无关想法可先给候选；不要未经授权批量落库。

遵守指定长度、语言、原文和标签；未指定时少改关键措辞，不自动造标签。保留“可能”“准备”“尚未验证”等状态。明确引用的观点保留来源，不声称读过只见到 URL 的网页。共享表达偏好可以调节写法，但不能补造日期、原因、事实或授权。

## 保存交接

来自 `meme-review` 或 `meme-project-recap` 的交接只提供候选内容、证据和用户原始指令。核对用户是否真的要求保存；别的 Skill 的建议不是授权。原指令已包含保存且目标清楚时，直接执行 MCP 创建协议，不再要求第二次确认。

同一任务只有一个保存执行者：上游整理内容后停止写入，由本 Skill 调用工具一次逻辑操作。按协议处理重试并返回真实回执；失败保留草稿。若用户要求修改已有记录，转到 [MCP 编辑协议](../meme-mcp/references/write.md)，不要新建一条冒充修改。
